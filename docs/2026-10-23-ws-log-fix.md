Before this fix the single-upstream native WS handler called `logTurn` immediately after preparing/forwarding the client frame. That reported `stored=false` and preparation-only duration even if terminal acceptance later succeeded. It also logged opaque frames as turns.

Now each processed `response.create` logs once: terminal delivery, local rejection, or transport abort. The accepted public id is used internally to compute `stored`; the existing field format does not expose ids or payloads. Duration includes the upstream turn and acceptance. Status remains relay/HTTP outcome: a delivered application-error frame can log200/storedfalse, like HTTP200 carrying an error event; an interrupted transport logs502. Socket-pin acceptance counts as retained even without shared registration. Queued frames that are never processed do not become completed-turn records.

No cache/retention/routing/wire changes. No new dependencies.
